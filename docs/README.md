# Granum documentation

**New user? Follow the [guided real-data course](https://granum.app/docs/course/start).** It takes an
attributed 120-image aerial sample from setup to import, inspection, recovery, real training/comparison,
scoped approval/export and byte-verified restore, with actual screenshots, captioned videos and
checkpoints. The measured models are weak; the course does not claim a production detector or a fully
reviewed sample. See [Getting started](getting-started.md) for the lesson map and downloads.

| Guide | For | What it covers |
|---|---|---|
| [Getting started](getting-started.md) | Everyone | Install, first import, first review, first training run |
| [Review and approval](review-and-shipping.md) | Reviewers, annotators, leads | Decisions, edits, recovery, exploratory versions and the separate approval gate |
| [Importing data](importing.md) | Data owners | Preflight checks, resolutions, CLI import, data roots |
| [Dashboard workspace](dashboard.md) | ML engineers | Rows, filters, charts, editing, detection tools, training dynamics |
| [Python SDK](python-sdk.md) | ML engineers | Tables, runs, metrics, samplers, formats, integrations |
| [Service and CLI](service.md) | Operators | Commands, configuration, REST API, security model |
| [Operational hardening](hardening.md) | Operators and reviewers | Approval policy, draft recovery, shared HTTPS, durability, backup and upgrade rehearsal |
| [Measured scale](scaling.md) | Operators and ML engineers | Reproducible workload results, view budgets, limitations |
| [Release qualification](release-qualification.md) | Release owners | Build provenance, artifact checksums, publishing gates, manual qualification |
| [Architecture](architecture.md) | Contributors | Data model, storage layout, components, design decisions |
| [Development](development.md) | Contributors | Dev setup, tests, builds, CI, conventions |
