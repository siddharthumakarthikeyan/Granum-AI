Service API reference

Find endpoint families, inspect the live schema and handle jobs, access errors and conflicting revisions.

The running service publishes its interactive OpenAPI documentation at http://127.0.0.1:8000/docs and its schema at /openapi.json. These are the authoritative request fields for that installed build. Replace the address when using a configured port or shared HTTPS host.

Read workspace state

curl http://127.0.0.1:8000/api/health
curl http://127.0.0.1:8000/api/projects

Shared mode requires authenticated HTTPS. Local Host/Origin checks are separate from authentication; do not disable them to make an unconfigured remote client work.

Shortened paths in a row continue that row's immediately preceding resource prefix; consult the live schema for exact paths and HTTP methods. For example, table commits use POST /api/table/commit, while table row reads use GET /api/table/rows.

Mutations and jobs

Writes use JSON request bodies and enforce the current workspace role. A request can start a job; poll its returned ID until a terminal status and inspect its result. A cancelled request is not necessarily proof that no intermediate work happened. Confirm current state before retrying.

Stale revisions and incompatible version/approval requests can return conflicts. Refresh the source, retain the user's draft and reconcile explicitly. Repeated arbitrary POSTs are not a general idempotency strategy. Audit completion failures can occur after a change was saved; follow the recovery procedure.

Scope

Legacy /api/licence/* routes remain in the service, but the current alpha disables licence enforcement. A public versioned external API guarantee, organisation API-key platform and compute-plugin API are Not yet included. Use exact build versions for automated clients.
